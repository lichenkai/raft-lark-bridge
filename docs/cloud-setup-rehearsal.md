# 云端配置 SOP 与用户预演

按一个飞书租户、两个 Raft 服务器和两名试点员工，走查从交付仓库到第一次使用。表格定义开发应提供的交互与上线操作。当前预演使用示例域名和模拟身份，执行时只展示下一步及预期结果。真实部署、应用发布、授权和消息收发按确认后的上线流程执行。 [平台设置指南](cloud-setup.md)

| 步骤 | 谁来做 | 看到什么才算完成 |
| --- | --- | --- |
| 部署一套服务 | 维护者把仓库交给 Codex 或其他开发 Agent，确认目标主机、HTTPS 域名、运行账号、固定版本与持久化位置。待实际部署时，按批准的运行定义启动并验证重启恢复 | Agent 列出健康检查、设置页、Raft 登录回调、飞书登录及卡片回调，每项显示当前状态和下一位处理人。域名不可达时先核反向代理、TLS 和路径 |
| 创建飞书机器人 | 飞书管理员在开放平台创建企业自建应用，开启机器人，配置应用发消息、身份绑定所需范围与卡片回调，发布给试点员工 | 飞书后台明确显示应用已发布、回调已验证、两名员工在可用范围。这里申请的是企业自建应用的机器人能力，无需申请飞书智能体 |
| 注册并安装 Raft App | 来源管理员确认一次注册卡。两个服务器的管理员各自安装，点 Raft 的「继续设置」进入桥接后台 | 设置页明确服务器、关联的飞书应用和可用能力，设置成功后回报该安装「已配置」。无权限时提示找哪个服务器的管理员 |
| 员工连接账号 | 员工登录 Raft 与飞书，确认收卡账号及所选服务器，选择个人卡、DM 或 @ 场景 | 页面显示绑定属谁、启用了哪些服务器及每个场景支持什么。个人卡、DM、个人 @ 分别核用户的事件投递和本人回写权限，并显示「可在飞书处理」「打开 Raft 处理」或「待开通」 |
| 体验第一张卡 | 员工点「发送测试卡」，打开机器人私聊中的消息并按可用方式作答 | 测试页分别显示「飞书投递」「收到本人点击」「Raft 原生回执」。只有第三步拿到原卡回执才显示闭环成功。模拟测试说明不会写入 Raft |
| 验普通 DM 和个人 @ | 两端权限具备时，第二名员工发一条 DM，并在任务中 @ 第一名员工，第一名员工从相应飞书卡回复 | 两条回复分别落到 Raft 原 DM 和原任务讨论，原回复显示本人。测试页分别记录投递、原位置与 Raft 新消息 ID。仅跳转和未开通也各自显示，卡片可用不代表 DM 或 @ 可用 |
| 验其他服务器及退出 | 从第二服务器发给另一名员工，然后撤销第一位的绑定 | 两人只收各自的卡。被撤销的旧卡失效，另一位仍能正常使用 |

开发验收按这张表逐步走。每一步要有成功条件、最常见失败时的提示和可重试入口。进入下一步前由当前角色核对结果。真实作答与回复需分别取得平台回执，才计入对应场景的闭环。 [问题卡验收矩阵](../specs/cloud-question-cards/verification.md) · [个人消息验收](../specs/personal-messages/spec.md)

## 给 Agent 的预演输入

> 请按仓库 Skill 在目标服务器预演云端 Raft 和飞书桥接。列出我的运行账号、两个平台需要的管理员动作、员工首次绑定和测试卡流程。使用示例地址，不创建应用或发送真实消息。

Agent 先查项目当前实现和设定，说明这是受审的预演。应用注册、分享、权限审批和个人登录需要对应身份。能模拟的检查单列为模拟结果，真实投递和原卡回写等待平台能力、部署件和试点确认。
