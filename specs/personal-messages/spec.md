# Raft 普通私信和个人提及

**状态** 已纳入设计，平台接口与实现待验证。个人卡片另见 [卡片清单](../cloud-question-cards/card-types.md)。

## 用户流程

用户在每个 Raft 服务器绑定账号并启用对应场景。开启普通私信后，新收到且仍有权查看的 DM 默认在飞书机器人私聊提醒，同一条消息只提醒一次。个人提及可单独开启，只接 Raft 实际投递给这个人的 @，包括频道、回复线程和任务讨论。用户无需另配每个频道、线程或任务。

飞书卡显示原文、发送者、来源服务器、会话或任务及原消息入口。在允许本人回复的场景，卡上提供文本输入和发送。Raft 正式保存新消息后，飞书才显示「已发送」。从两边打开时都可以在 Raft 找到同一段上下文。飞书交互不可用或超出有效期时，用户可点回 Raft 继续。

## 位置、权限和授权

使用 Raft 事件给的服务器、会话种类、原消息 ID、现有线程或任务 ID 和收件人。普通 DM 或频道根消息用 Raft 的原生回复入口。已在线程中时回复同一个线程，任务讨论走原任务回复。所有回复都必须以实际用户身份在 Raft 记账，发送时由 Raft 校验会话和用户权限。

若同一消息已有具名个人卡且又触发个人 @，只向该用户投递一次，使用已适配的卡片路径。本人发送、桥接写回的同一消息和回调重试按稳定 ID 去重，避免自我回送。解除绑定、用户退出或撤销安装后停止接收和提交。桥接的私聊发送范围只涵盖明确授权的本人。

平台待核两项能力。第一项是按真人授权获取 DM、个人提及及足够的原消息定位。第二项是按本人授权向原会话发出普通回复，返回新消息 ID，并可按幂等提交号回读。公开 Agent API 的收发用 Agent 身份；原卡作答许可与普通消息回复分别核实。只有投递能力时，可以提供提醒和原消息入口。 [Raft Activity](https://docs.raft.build/catch-up-in-one-place/) · [Raft 消息与线程](https://docs.raft.build/features/messaging/messages/) · [Raft App 事件目录](https://docs.raft.build/developers/raft-apps/build/#app-notifications-catalog)

## 验收

| 前置条件 | 操作 | 预期与证据 |
| --- | --- | --- |
| 两个不同的原 DM 消息，收件人为同一人 | 以相反顺序在飞书输入并提交各自回复 | 两条都以本人身份到正确原会话和消息，分别记录 Raft 新消息 ID |
| 同人受邀进入频道、线程与任务讨论 | 各收到一次真实个人 @，并夹入一条普通频道文本 | 只收实际 @，能点回各来源；回复进入原线程或任务讨论 |
| 一条具名卡同时触发个人 @ | 两种事件以任意先后到达 | 对同一收件人只有一张飞书卡，做原生作答时只有一条原生回执 |
| 可模拟平台接收后响应丢失 | 重放回调、进程重启并恢复同一提交 | Raft 一条新回复，飞书显示实际发送状态 |
| 权限被收回或账号重绑 | 从旧卡尝试提交 | 旧回调不能使用新授权发消息；原会话保持正常 |
| 交互失效或服务器仅支持投递 | 点开原消息 | 保留原入口、身份和可见性，用户能在 Raft 原位置继续 |

当前真实联调均待测。开发者交模拟、重试和位置映射证据，独立评审者核不同来源、跨服务器和撤权反例。
