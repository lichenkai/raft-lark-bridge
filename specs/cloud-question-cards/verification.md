# 云端问题卡验收

当前为计划。云端真实验收状态均为待测。测试记录包含 feature 提交、部署版本、实际服务器和已脱敏证据。代码评审对照下列场景及 [协议](protocol.md)。

| 前置条件 | 操作 | 预期结果与证据 | 执行 |
| --- | --- | --- | --- |
| 两个 Raft 服务器、两个试点人、同一飞书应用已启用 | 首次连接并在各服务器发测试卡 | 用户独立完成连接；卡只到有权限的指定飞书账号。设置页显示真实能力、来源服务器和原卡链接 | 维护者、试点用户 |
| 应用支持飞书直接作答 | 对具名确认卡点击原选项 | 原卡记本人和同一个原选项，发卡人收一条原生回执；飞书随回执更新。保留两端卡 ID 和结果 | 开发、试点用户 |
| 应用只支持投递，或卡含未支持的题型和「其他…」 | 收卡后打开原卡 | 飞书显示原卡入口；可在 Raft 完成全部原选项。已支持的题目、说明、顺序相同 | 开发、评审 |
| 收件人、应用或服务器不同 | 以另一人点击，或重放到不同绑定 | 拒绝提交。原卡状态不变；无跨服务器、租户或公开群投递 | 开发、评审 |
| 两端均可作答 | 双击、重复推送回调或网页版抢先选不同答案 | Raft 只有一笔有效答复，飞书显示实际答案，发卡人只收到原生回执 | 开发、评审 |
| 可模拟提交响应丢失 | Raft 已保存后断开，或飞书卡面更新失败 | 超时先查原卡再决定重试；已回答只修飞书卡面；完整保留同一个提交号和原生回执 | 开发、评审 |
| 允许复用旧卡 | 改绑定或解绑重绑，再点旧卡；分别撤回和过期 | 拒绝旧绑定提交，原卡答案保持，飞书状态与原卡一致 | 开发、评审 |
| 有未结束的旧版消息 | 升级桥接后点旧卡、再收到新格式卡 | 旧映射可继续使用；未知作答约束走原卡；保持原选项值和绑定版本 | 开发、评审 |
| 可中断桥接任务 | 在入队、确认游标或提交回执之间重启 | 恢复未完成项；原卡和飞书均无重复处理造成的可观察副作用 | 开发、评审 |
| 已启用本地桥接 | 改动云端配置后重跑现有本地测试，并验证独立工作目录 | `npm test` 继续通过，配置、凭据和个人引用回信流程各自可用 | 开发、评审 |
| 管理员要停用部分链路 | 撤销其中一个服务器的安装或一人的绑定 | 只停止该范围的新投递和作答，其他服务器和人继续使用 | 维护者、评审 |

自动化验证使用脱敏原卡、模拟事件和回执、签名有效及无效的样例。平台真实验证使用明确的测试卡及约定账号。对实际执行操作的审批，首版验证原卡跳转及 Raft 自有权限流程。
