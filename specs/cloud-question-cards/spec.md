# 云端 Raft 原生问题卡

**状态** 需求与方向已确认，云端代码及平台联调待实现。Raft 平台接口见 [协议](protocol.md)。

## 用户目标

在多个 Raft 服务器工作的员工，可以从一个飞书机器人私聊收自己的 Raft 原生问题卡。支持直接作答的卡，在飞书选完后，由 Raft 记录该员工的原生答案并向发卡人产生原生回执。桥接在现有项目扩展，通过一套云端服务服务多个用户。现有本地文字桥接按原路径使用。

## 首版流程

1. 管理员把同一个 Raft App 安装到试点服务器，把飞书机器人开放给试点用户。
2. 用户从设置页完成 Raft 与飞书身份确认，选服务器并启用接收。页面显示当前账号、每个服务器的能力、授权状态和重连入口。
3. 用户先走一张测试卡。比如 Raft 创建「请确认已看过发布说明」，飞书显示原题和「已阅读」。卡片另有来源服务器、原卡入口和状态。
4. 收到具名原卡后，用户在飞书选择答案。飞书告知正在提交，Raft 最终确认后才显示已回答。发卡人从原 Raft 对话看到本人的原生回执。
5. 用户可单独关闭某个服务器或解除飞书账号绑定。已投递的旧卡无法沿再次创建的绑定继续提交。

## 卡片范围

桥接按版本读取结构化原卡，保留题目、说明、选项、顺序和截止时间，用统一的飞书模板呈现。答案按原题目 ID 和选项值回传。首批支持具名的一键确认和能够完整表达的单选卡。自动提供的「其他…」也是原卡的一部分，首版模板无法完整表示时，整张卡走原卡作答。未知题型、带未支持校验的表单、可实际执行操作的审批沿 Raft 原入口处理。允许转发的类型、已适配的格式版本与呈现方式见 [卡片盘点](card-types.md)。

| Raft 可用能力 | 可交付体验 |
| --- | --- |
| 按收件人投递及读状态 | 飞书私聊提醒和打开原卡 |
| 投递、读状态及本人授权作答 | 可完整映射的卡在飞书直接作答 |
| 投递尚无平台支持 | 可开发和模拟验证连接、映射与失败路径。用户引导说明原生卡尚未可用。 |

## 交付与分工

- 开发负责人维护仓库文档、平台接口核实和实现，独立评审者按本 spec 和 [验收矩阵](verification.md) 核代码。
- 第一步核实 Raft 能力，给出平台支持边界及最小真实回证。连接与消息处理用脱敏卡片做程序验证。可投递后用两人、两个服务器核绑定与原卡链接。可作答后补原生回执、异常和升级兼容。
- 每次迭代从 `main` 开 feature 分支，按 [贡献指南](../../CONTRIBUTING.md) 留规格、实际提交和验证结果。同一套部署引导可被人和 Agent 使用。 [云端设置](../../docs/cloud-setup.md) · [架构](../../docs/architecture.md)
