# 链路追踪

每个 Raft 服务器的桥接设置可单独打开链路追踪。开启并指定一个飞书群后，同一个桥接应用机器人为已确认的投递和原生回复各向该群发送一条通知。默认关闭。

## 配置与使用

1. Raft 服务器的桥接管理员选定允许查看传递双方的飞书群，并让飞书群管理员将同一个应用机器人加进去。用该应用可见的群列表确认目标群，复制其 `chat_id`。
2. 在该服务器的桥接设置页填入群 ID。点「发送测试通知」，核目标群显示机器人发的一条无个人信息的测试记录。发送失败时给出群 ID、机器人未入群或无法发送等可确认的原因。验证后再开启。换群需重新验证。
3. 用同一条测试消息验投递和回写。群里两条通知应有相同追踪编号。关闭后再测试一条，飞书收发和 Raft 写回继续可用，群里无新增记录。 [配置 SOP](../../docs/cloud-setup-rehearsal.md)

## 事件与边界

- 投递使用飞书确认的成功时间。回复使用 Raft 原卡作答或原会话回复的确认时间。通知晚发沿用原确认时间，两条事件引用同一条用途仅为关联的追踪编号。
- 通知只放事件方向、平台已授权展示的发送与接收方名称、确认时间和追踪编号。采用原卡允许展示的署名。正文、选项、答案、附件、原聊天链接和凭据不纳入通知。界面提示群成员能看见双方及时间。
- 以稳定投递关联加事件种类去重。Raft 回执确认后才产生回复追踪。追踪与主操作的重试分开。机器人移出群、群限流或追踪发送失败时，主链路继续。旧群待发通知不能自动转到新群。关闭后停止该服务器的新通知和待发通知。
- 配置按 Raft 服务器生效。一个服务器的开关、群或投递状态不会改变另一服务器。追踪群消息不作为桥接入站事件。

## 验收

| 条件 | 预期 |
| --- | --- |
| 成功投递后飞书作答，Raft 返回原生回执 | 两条通知同号，方向相反。各自时间与原平台确认一致 |
| 同一事件重放，或者首次发送超时 | 复用同一通知关联，确认原发送记录后再重试。群里一类事件只出现一次 |
| 群 ID 填错、机器人未入群、或主流程已经成功但追踪发送受限 | 设置页提示错误或显示追踪待处理，主链路按实际结果继续 |
| 关闭、切换群、卸载、另一服务器启用 | 停止旧目的地发送。不同服务器的记录只去自己的已验证群 |
| 输入带正文、选项、附件、敏感值或伪造的署名 | 通知只呈现已授权展示的双方、时间、方向和编号 |
